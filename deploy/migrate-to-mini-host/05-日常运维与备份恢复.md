# 05 · 日常运维与备份恢复

> 小主机部署完成后的日常管理速查手册。所有操作都在 SSH 里完成。

---

## 📋 PM2 进程管理

### 查看状态

```bash
pm2 status              # 看所有进程
pm2 list                 # 同上
pm2 show xlover-backend  # 看后端详情
pm2 monit                # 实时监控（CPU/内存/日志）
```

### 重启 / 停止

```bash
pm2 restart xlover-backend   # 重启后端
pm2 restart xlover-tunnel    # 重启隧道
pm2 restart all              # 重启全部
pm2 stop xlover-backend      # 停止
pm2 start xlover-backend     # 启动
```

### 查看日志

```bash
pm2 logs xlover-backend --lines 50        # 后端最近50行
pm2 logs xlover-tunnel --lines 50        # 隧道日志
pm2 logs --lines 100                      # 全部日志
pm2 logs xlover-backend --lines 0 --wait  # 实时跟踪（类似 tail -f）
```

### 更新代码后重启

```bash
# SSH 登录后
cd ~/Xlover-Server
git pull      # 如果用 git 管理
# 或上传新代码后
npm install --omit=dev
pm2 restart xlover-backend
```

## 💾 数据库备份

### 手动备份

```bash
cd ~/Xlover-Server
./backup-db.sh
# 备份文件在 database/backups/xlover.db.YYYYMMDD-HHMMSS.gz
```

### 自动备份（每天凌晨 3 点）

```bash
# 编辑 crontab
crontab -e

# 添加一行：
0 3 * * * /home/xlover/Xlover-Server/backup-db.sh >> /home/xlover/Xlover-Server/logs/backup.log 2>&1

# 保存退出（nano 编辑器：Ctrl+O → Enter → Ctrl+X）
```

### 查看备份

```bash
ls -lh ~/Xlover-Server/database/backups/
# 保留最近 30 天
```

## 📤 恢复数据库

### 从备份恢复

```bash
cd ~/Xlover-Server

# 1. 停后端
pm2 stop xlover-backend

# 2. 备份当前数据库（保险）
cp database/xlover.db database/xlover.db.before-restore

# 3. 解压备份并覆盖
gunzip < database/backups/xlover.db.20260901-030000.gz > database/xlover.db

# 4. 启动后端
pm2 start xlover-backend

# 5. 验证
curl http://localhost:3000/health
```

### 从 Windows 上的原始数据库恢复（跨系统迁移）

```bash
# 1. 把 Windows 上的 xlover.db 传到小主机
#    在 Windows PowerShell：
#    scp d:\AI\豆包\Xlover3.0\Xlover-Server\database\xlover.db xlover@小主机IP:~/Xlover-Server/database/

# 2. SSH 登录，停后端
pm2 stop xlover-backend

# 3. 覆盖
cp ~/Xlover-Server/database/xlover.db ~/Xlover-Server/database/xlover.db

# 4. 启动
pm2 start xlover-backend
```

## 🔄 系统更新

### 更新 Debian 系统

```bash
sudo apt update && sudo apt upgrade -y
# 一般不需要重启，但大版本内核更新建议重启：
sudo reboot
# PM2 会自动恢复（已配开机自启）
```

### 更新 Node.js

```bash
# 查看当前版本
node -v

# 升级到最新 v20 LTS
curl -fsSL https://deb.nodesource.com/setup_20.x | sudo bash -
sudo apt install -y nodejs

# 重启后端（better-sqlite3 可能需要重新编译）
cd ~/Xlover-Server
npm rebuild better-sqlite3
pm2 restart xlover-backend
```

### 更新 cloudflared

```bash
cloudflared update    # 自动检查并更新
pm2 restart xlover-tunnel
```

## 🌐 Cloudflare 域名相关

### 查看当前隧道状态

```bash
# 在小主机上
cloudflared tunnel info xlover-backend

# 或浏览器访问
# https://one.dash.cloudflare.com/ → Networks → Tunnels
```

### 查看公网域名

```bash
# 查看 config.yml
cat ~/Xlover-Server/.cloudflared/config.yml | grep hostname
```

### 域名访问不了排查

```bash
# 1. cloudflared 是否在运行
pm2 status    # xlover-tunnel 应是 online

# 2. 看隧道日志
pm2 logs xlover-tunnel --lines 30

# 3. 本地后端是否正常
curl http://localhost:3000/health

# 4. DNS 是否正确（在 Windows 上）
nslookup xlover.你的域名.com
# 应解析到 Cloudflare 的 IP

# 5. 公网验证
curl https://xlover.你的域名.com/health
```

## 🚨 应急处理

### 后端崩溃不停重启

```bash
pm2 logs xlover-backend --lines 100   # 看错误
# 常见原因：数据库锁死 / 端口占用 / 依赖损坏

# 修复数据库
pm2 stop xlover-backend
sqlite3 database/xlover.db ".recover" > /tmp/recovered.db
mv /tmp/recovered.db database/xlover.db
pm2 start xlover-backend
```

### 端口 3000 被占用

```bash
sudo lsof -i :3000   # 看谁占用了
# 或
sudo ss -tlnp | grep 3000

# 杀掉占用进程
sudo kill -9 <PID>

# 重启后端
pm2 restart xlover-backend
```

### 小主机断电后恢复

PM2 已配置开机自启，正常情况来电后自动恢复：
```bash
# 登录后检查
pm2 status
# 如果没自动启动
pm2 resurrect
```
